Scope & Future Vision

What this prototype is, and what it is deliberately not yet.

We keep the boundary between “works today” and “planned” explicit. Everything labelled implemented is live and tested end-to-end; everything below is a direction, not a promise, and none of it is present in the current build.

In scope · this build

The clinical workflow, end to end

Roles (patient / doctor / admin), consent, adaptive intake, returning-visit intelligence, documents & OCR, structured context, doctor verification, emergency safety net, and a complete audit trail — all on real, persisted records.

Next · production hardening

From prototype to deployable

  • Production PostgreSQL with migrations; structured concurrency for document jobs.
  • Pluggable real AI/OCR providers behind the existing interfaces (OpenAI or institute stack).
  • Redis-backed background queue for OCR and summarization at scale.
  • Observability: structured logs, request tracing, and provider cost tracking.
Later · ecosystem

Interoperability & reach

  • FHIR R4 server export and ABHA / ABDM health-id linkage.
  • SMS / WhatsApp alerts for verification and emergency follow-through.
  • Multi-hospital, multi-tenant administration and referral workflows.
  • Longitudinal analytics on de-identified, consented data.
A note on AI in this prototype

The language model, OCR and speech services run on deterministic demo providers. They exist to exercise the full clinical workflow — permissions, provenance, verification, emergency rules, audit — without depending on an external vendor. The value of this build is the system around the model, and every model-facing boundary is an interface a production provider would slot into.

Roadmap items are directions, not commitments. Nothing unlisted exists in this build.
